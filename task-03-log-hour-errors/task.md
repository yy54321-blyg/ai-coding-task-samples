# Task 03 · 按小时统计日志中的 ERROR 数量

## 需求

读取一个日志文件，统计**每小时**出现的 `ERROR` 级别日志条数，输出为 CSV。

**日志格式（每行）：**

```
2025-03-01 12:34:56 [ERROR] something failed
2025-03-01 12:59:01 [INFO] started
```

**规则：**

1. 只统计级别为 `ERROR` 的行（级别写在方括号里，大写）
2. **消息正文中出现 "ERROR" 字样不算**（如 `[INFO] retry ERROR handler`）
3. 时间格式固定为 `%Y-%m-%d %H:%M:%S`
4. 无法解析的行计入 `skipped`，**不中断处理**
5. 输出 CSV：`hour,count`，`hour` 格式 `YYYY-MM-DD HH:00`
6. 输出按时间**升序**
7. 支持 `--top N`：只打印前 N 行到终端（CSV 仍输出全部）

---

## 输入示例

`app.log`

```
2025-03-01 12:34:56 [ERROR] db timeout
2025-03-01 12:59:01 [INFO] retry ERROR handler
2025-03-01 12:05:00 [ERROR] disk full
2025-03-01 13:00:01 [ERROR] db timeout
2025-03-02 00:10:00 [ERROR] rollover
this line is garbage
2025-03-01 23:59:59 [ERROR] final
```

## 期望输出

`error_per_hour.csv`

```csv
hour,count
2025-03-01 12:00,2
2025-03-01 13:00,1
2025-03-01 23:00,1
2025-03-02 00:00,1
```

统计：写入 4 个小时的数据，跳过 1 行

> 注意：`[INFO] retry ERROR handler` **不计入**，因为它不是 ERROR 级别。

---

## 验收标准（可测）

- [ ] 上述输入产生上述 4 行 CSV，**顺序为时间升序**
- [ ] `[INFO] retry ERROR handler` **未被统计**（消息正文里的 ERROR 不算）
- [ ] 垃圾行 `this line is garbage` 被跳过，且不影响其他行的统计
- [ ] 跨天（`2025-03-01 23:59:59` 与 `2025-03-02 00:10:00`）分到不同的两小时
- [ ] 小时部分补零为 `HH:00`（不是 `12:0` 或 `12`）
- [ ] 日志文件为空时，输出只有表头，且退出码为 0
- [ ] `--top 2` 时终端只打印 2 行，CSV 仍有 4 行

---

## 难度

**中等偏低**

涉及能力：
- 正则的**精确性**（区分「级别字段」与「正文内容」）
- 脏数据容错
- 字典聚合 + 排序
- 输出格式规范化

---

## 常见错误（AI 典型失败模式）

| # | 错误 | 正确做法 |
|---|---|---|
| 1 | 用 `"ERROR" in line` 判断 → **把正文里的 ERROR 也算进去** | 用正则锚定方括号：`^\S+ \S+ \[ERROR\]` |
| 2 | 直接遍历 dict 输出 → 顺序随机 | `sorted(items)` 或 `sorted(d.items())` |
| 3 | 一行解析失败就 `raise`，整个脚本退出 | 每行单独 `try/except`，累计 skipped |
| 4 | 只截取到小时但**不补零**（`12:0`），导致字符串排序错乱 | 用 `dt.strftime("%Y-%m-%d %H:00")` |
| 5 | 正则写成 `\[.*\]`，贪婪匹配到多个方括号 | 明确写 `\[ERROR\]` |
| 6 | CSV 用 `utf-8` 输出，Excel 打开乱码 | 用 `utf-8-sig` |
| 7 | 把 `[ERROR]` 和 `[error]` 都算，导致误计 | 题目已规定大写；如需兼容须显式声明 |
| 8 | 未处理空文件，`max()` 或索引操作抛异常 | 空输入直接输出表头 |

---

## 为什么这个任务适合评测

- **正则精确性是核心考点**：这是"能读懂需求"和"能实现需求"的分界线
- **容错能力可测**：一行脏数据就崩溃的代码，是典型的低质量产出
- **输出确定**：给定输入，CSV 内容唯一，便于自动判定
- **业务真实**：所有运维/后端场景都有这个需求
