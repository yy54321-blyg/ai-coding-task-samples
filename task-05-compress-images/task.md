# Task 05 · 批量压缩图片到指定体积以内

## 需求

递归处理目录下的图片，把每张图压到 **≤ 200 KB**，同时保证**最长边 ≤ 1920 px**。

**规则：**

1. 支持 `.jpg` / `.jpeg` / `.png`；**跳过 `.gif` 与其它文件**
2. 压缩策略：
   - 先固定分辨率，**二分搜索 JPEG quality**（范围 90 → 20），取能满足体积的最大质量
   - quality 降到 20 仍超标时，按 0.8 比例**逐步缩小分辨率**后重试
3. PNG 处理：
   - 有透明通道 → **白底合成后转 JPEG**（不能出现黑底）
   - 无透明通道 → 同样走 JPEG 流程
4. **不修改原文件**；输出到 `out/`，**保持原有相对目录结构**
5. 原图已满足「≤200KB 且最长边 ≤1920」时，**直接复制，不重新编码**（避免二次失真）
6. 输出报告：`原大小 → 新大小`，并标记是否达标

---

## 输入示例

```
in/
├── big.jpg        (5.2 MB, 4000×3000)
├── small.png      (120 KB, 800×600)
├── logo.png       (300 KB, 1200×1200, 带透明通道)
├── anim.gif       (2 MB, 动图)
└── sub/
    └── photo.JPG  (1.8 MB, 3000×2000)
```

## 期望输出

```
out/
├── big.jpg        (≤200 KB, 最长边 ≤1920)
├── small.png      (原样复制，≈120 KB)
├── logo.jpg       (≤200 KB, 白底，无黑块)
└── sub/
    └── photo.jpg  (≤200 KB)

报告:
in/big.jpg      5.2 MB -> 186 KB   OK
in/small.png    120 KB -> 120 KB   OK(跳过重编码)
in/logo.png     300 KB -> 142 KB   OK(转JPEG)
in/anim.gif     - 跳过(gif)
in/sub/photo.JPG 1.8 MB -> 173 KB  OK
```

---

## 验收标准（可测）

- [ ] `big.jpg` 输出文件 **≤ 200 KB**，且最长边 **≤ 1920 px**
- [ ] `small.png` 未重新编码（文件大小、哈希与原图一致）
- [ ] `logo.png` 转为 JPEG 后，透明区域为**白色**，不是黑色
- [ ] `out/` 的目录结构与 `in/` 一致（含 `sub/` 子目录）
- [ ] `anim.gif` 被跳过，**不出现在输出目录**
- [ ] 原 `in/` 目录下**所有文件的 size 与 mtime 均未变化**
- [ ] 输出扩展名统一为 `.jpg`（`photo.JPG` → `photo.jpg`）
- [ ] 处理 100 张图时不出现**无限循环**（有明确的最大重试次数）

---

## 难度

**中等偏高**

涉及能力：
- 图片编码原理（有损/无损、quality 与体积的非线性关系）
- 色彩模式（`RGB` / `RGBA` / `P` / `LA`）与透明通道处理
- 二分搜索
- 递归目录遍历 + 相对路径映射
- 幂等与「不破坏输入」的工程习惯

---

## 常见错误（AI 典型失败模式）

| # | 错误 | 正确做法 |
|---|---|---|
| 1 | `RGBA` 直接 `save("x.jpg")` → `OSError: cannot write mode RGBA as JPEG` | 先 `convert("RGB")` 或白底合成 |
| 2 | 透明 PNG 直接 `convert("RGB")` → **透明区域变黑** | `Image.new("RGB", size, (255,255,255))` 后 `paste` 带 mask |
| 3 | **死循环/无限缩小**：`while size > target: quality -= 5` 到 0 后卡死 | 二分搜索 + 缩小次数上限 |
| 4 | 直接覆盖原文件 | 输出到 `out/`，原目录只读 |
| 5 | 只用 `quality` 降，**不缩分辨率** → 大图永远压不下去 | 质量降到下限后改缩边 |
| 6 | 对已达标的小图也重新编码 → 体积反而变化、画质下降 | 先判断，达标就复制 |
| 7 | 丢失 EXIF 方向信息 → 手机竖拍照变成横躺 | `ImageOps.exif_transpose()` |
| 8 | 递归遍历写错，子目录结构被压平 | 用 `relative_to()` 还原相对路径 |
| 9 | 忽略 `P` 模式 + `transparency` 的 PNG，转 JPEG 后异常 | 判断 `mode` 与 `info["transparency"]` |

---

## 为什么这个任务适合评测

- **难点集中在"边界"而不是"主逻辑"**：主逻辑三行就能写完，失败全在透明通道、已达标判定、无限循环
- **失败结果可肉眼验证**：黑底、模糊、体积超标都是可见错误
- **有真实的工程取舍**：质量 vs 体积 vs 分辨率，需要判断
- **可自动判定**：体积、尺寸、哈希、目录结构都能用脚本比对
